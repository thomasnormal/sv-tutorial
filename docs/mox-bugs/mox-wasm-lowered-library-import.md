# Lowered-library browser import boundary

Item 23 keeps the precompiled `uvm_pkg` artifact and the generic manifest-driven
consumer, but browser qualification is waiting on the Mox consumer tool.

The pinned mapped-Moore artifact is `static/mox/packages/uvm_pkg-b90b3a5.vlib`
(58,912,612 bytes; SHA-256
`058e528f971d915e06fe87499a3c895bd927d4dcb9f6f86bc5680c2dfe1ead11`). The
native receipt at Mox `b90b3a51a68b772a1510c837166afd6d429d8f20` is recorded in
`/tmp/svt-uvm-receipt-all.md`: source-backed rows complete in about 40–54 s,
while mapped-vlib rows take about 80–113 s and four rows time out at 120 s.
The browser `uvm/reporting` probe reached mapped-vlib diagnostics but did not
return within 900 s.

Interp's in-progress general consumer first adds
`mox-run --read-vlib-lowered-library-ir=<file>` alongside ordinary sources,
but the coordinator has ruled that the browser stays on the existing
`mox-verilog` → `mox-sim` pipeline. The same shared frontend boundary must
therefore be exposed by `mox-verilog`; the site must not switch to a separate
browser `mox-run` artifact. The manifest remains on the validated mapped-vlib
path, and UVM browser rows stay timeout-dispositioned until the shared
lowered-library consumer is landed.

## Native consumer qualification (2026-11-03)

Interp's native `mox-run` target now compiles from the in-progress patch. A
matching artifact generated by its `mox-verilog` (`4d186a68b23`) is 59,208,919
bytes and passes the sectioned-container identity and core-state checks. An
artifact-only `mox-run --compile-only` invocation loads it in 2,849 ms and
reports the `uvm_pkg` library-owned symbol roots.

The ordinary-source handoff is not yet usable: with `--no-uvm-auto-include`,
`--read-vlib-lowered-library-ir=<artifact>`, `-I static/mox/uvm-core/src`, and a
lesson source containing `import uvm_pkg::*`, Slang reports `unknown package
'uvm_pkg'`. Replaying `uvm_pkg.sv` to make the frontend see the package instead
creates a duplicate `uvm_pkg::uvm_test_done` definition. This proves the
remaining issue is the generic declaration visibility boundary between the
serialized lowered package and ordinary source import; it is not artifact
fetch, identity validation, or MLIR materialization.
