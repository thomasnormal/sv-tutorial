Real cocotb tests are usually synchronized to clock edges, not fixed delays. This lesson uses the same quickstart style pattern: cocotb.start_soon(Clock(...).start()) plus await RisingEdge(...).

Open reg_en.sv and implement a 4-bit register with synchronous reset and enable: on each rising edge, reset should clear q, otherwise q should load d only when en is high.

The Python test (test_reg_en.py) checks:

  • reset behavior on a rising edge
  • hold behavior when en=0
  • load behavior when en=1
  • edge-based waiting with RisingEdge, FallingEdge, and ClockCycles

Edge-by-edge register trace

first RisingEdgerst=1, en=0, d=0reset clears q to 0
next RisingEdgerst=0, en=1, d=Aenable loads q=A; ReadOnly observes the committed NBA
next RisingEdgeen=0, d=3the register holds q=A because the enable is low
two ClockCycles lateren=1, d=4the final enabled edge loads q=4

Clock drives a repeating 10 ns waveform, FallingEdge gives the coroutine a safe half-cycle to change inputs, and RisingEdge synchronizes the check to the register's sampling edge. ReadOnly is the observation phase after the nonblocking assignment has committed.

Known limitation: the pinned WASM VPI artifact does not deliver the §38.36.1 value-change callback after a cocotb clock write, so this edge-trigger run remains a documented Mox refusal. You can still run the same test with a native cocotb simulator.
