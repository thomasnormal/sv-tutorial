A clocking block input is a sampled value, not a live alias of the signal. An explicit #0 input skew samples in the Observed region, after the Active-region writer has run.

Exercise

Add the explicit #0 skew to cb.sig. The testbench writes BB in an Active-region process, then writes CC after the clocking event has published its sample. The correct solution therefore observes BB at the first event, keeps BB through the same-slot Reactive re-entry and the following negedge, and samples BB again at the next positive edge.

clocking cb @(posedge clk);
  input #0 sig;
endclocking

Without #0, the default 1step input skew samples in the preceding Postponed region and the starter observes the old AA value. The clocking input still retains that sample until the next clocking event.

IEEE 1800-2023 §14.3 says the default input skew is 1step and samples the preceding Postponed region. §14.13 says that an explicit #0 samples in Observed, makes the new value available before the clocking-block event wakes its waiters, and does not resample during same-slot Active re-entry after Reactive unless a new clocking event occurs.

What landed in Mox

Mox's MQ93 M2 regression lock is 3b1760ff203; it preserves this sampler-retention behavior in both interpreter and compiled execution. The browser's Run action uses the pinned WASM runtime, while the native receipts record the current lesson's interpreter, compile, and reference runs separately.
