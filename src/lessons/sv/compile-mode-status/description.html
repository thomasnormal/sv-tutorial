This chapter is a status page for native Mox AOT simulation, not a claim that the browser runs every lesson in compile mode. The browser's Run button uses the pinned WASM runtime; the native command below is the way to check --mode=compile on the current toolchain.

Runnable example

Correct the arithmetic operation so the testbench observes the expected sum. The finished source is deliberately small: it passes in both native interpreter and compile modes, so it is a useful smoke test before investigating a larger refusal.

taskset -c 0-79 timeout --kill-after=3s 30s \
  /var/tmp/thomas-ahle/wt/landing/build-dev-fast/bin/mox-run \
  --single-unit --timescale=1ns/1ns --mode=compile \
  --max-wall-ms=25000 src/compile_mode_status.sol.sv

For this lesson, a successful compile-mode run prints PASS: compile-ready design sum=5. The browser lesson run is a separate interpreter-backed smoke check; it does not qualify the native AOT path.

What a refusal means

Compile mode refuses before simulation when its AOT obligations cannot be satisfied. It does not silently fall back to interpretation. The current census vocabulary classifies the result:

StatusMeaning
AGREECompile passes, parity matches the frozen interpreter oracle, and the AOT counters are clean.
HELDThe compile stage refuses with the same recorded provider-dirty or mandatory-retain facts as the census.
HELD-CHANGEDThe same stage refuses, but its refusal details changed.
NEW-REFUSALThe refusal occurs at a stage different from the ledger.
DIVERGECompilation reaches simulation, but the verdict or observable output differs.
ORACLE-DRIFTThe interpreter result differs from the frozen oracle; stop instead of blaming AOT.
