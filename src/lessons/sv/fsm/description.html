For any synchronous finite-state machine, start with this reusable two-block shape:

typedef enum logic [N-1:0] { <STATE_A>, <STATE_B> } state_t;
state_t state, next;

always_ff @(posedge clk)
  state <= next;

always_comb begin
  next = state;              // hold unless a branch changes it
  <outputs> = '0;            // give every output a safe default
  case (state)
    <STATE_A>: ...
    <STATE_B>: ...
    default:   next = <STATE_A>;
  endcase
end

The always_ff block is the only place that stores state. The always_comb block calculates next and decodes the current state into outputs. Starting with next = state means an unmentioned transition holds its state; assigning output defaults before the case means every branch drives a value instead of inferring storage. The SRAM contents are unknown until a write, and the controller test deliberately checks its control outputs rather than assuming an initial memory value.

A Moore FSM separates state memory from output computation into two always blocks. The memory access controller decides when and how the SRAM gets written or read:

  • IDLE — waiting for a command; assert ready=1. On the next cycle, transition to WRITING if cmd_valid && cmd_we, to READING if cmd_valid && !cmd_we, otherwise stay in IDLE.
  • READING — assert sram_we=0 and return to IDLE next cycle
  • WRITING — assert sram_we=1 and return to IDLE next cycle

Open mem_ctrl.sv. The two-always skeleton and default assignments are already set up. Fill in the case branches inside always_comb: the transition conditions in IDLE, and the output + transition for READING and WRITING.

Important: Do not modify state in your solution — state is updated only by the always_ff block. In always_comb you only assign to next (and the outputs). The combinational block computes the next state; the flip-flop block applies it on the clock edge.

That ordering gives the controller a one-cycle rhythm: a command sampled while in IDLE selects READING or WRITING for the next edge, and the corresponding output is visible during that state. The following edge returns to IDLE, where ready is high again.

Keep outputs in the always_comb block, never in the always_ff block — Moore outputs are a function of state only, not of the current inputs. A Mealy FSM would also allow outputs to depend directly on inputs, giving a one-cycle faster response — but at the cost of glitchy combinational outputs that change mid-cycle whenever inputs change. Moore is the safer default for synchronous RTL.
