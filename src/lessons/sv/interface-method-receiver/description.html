A method declared inside an interface runs in the scope of the interface instance that receives the call. That matters when a class stores a virtual interface: the handle selects an instance, and every method call through it must keep that receiver.

Exercise

The testbench creates two instances of the same interface. Bind the class's virtual-interface handle to u_b, then check the ordinary, cast, and parenthesized calls. The two instances return different answers so a call that silently uses the wrong receiver is visible.

class holder;
  virtual probe_if vif;
endclass

holder h = new;
h.vif = u_b;
string path = string'(h.vif.getPath());
int answer = (h.vif.getAnswer());

The starter deliberately binds u_a. Change that binding so all three path forms name the u_b instance and both answer forms return 2.

IEEE 1800-2023 §21.2.1.5 says %m prints the hierarchical name of the design element or subroutine that invokes the system task containing it. Section §25.9 defines a virtual interface as a variable representing an interface instance; after initialization, the underlying instance's components are available through dot notation, and virtual interfaces may be passed to methods.

What landed in Mox
