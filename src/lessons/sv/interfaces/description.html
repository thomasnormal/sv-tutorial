The SRAM testbench and the DUT currently need the same clock, write-enable, address, and data signals. Passing each wire separately makes a growing bus hard to read and easy to misconnect. An interface groups those signals into one shared connection:

testbench                         SRAM
  bus.we ─────────────────────────► bus.we
  bus.addr ───────────────────────► bus.addr
  bus.wdata ──────────────────────► bus.wdata
  bus.rdata ◄────────────────────── bus.rdata
             one shared mem_if bus

The general shape is:

interface <name> ([input|output] <type> <port>, ...);
    <type>       <signal>;
    <type> [N:0] <signal>;
    ...
    function <type> <name>(); ... endfunction
endinterface

An interface instance is shared by reference: the testbench and sram see the same live signals. This differs from a packed struct, whose fields form a value that is copied when it is passed around.

With this interface, the SRAM module needs one port:

module sram (mem_if bus);
  logic [7:0] mem [0:15];

  always_ff @(posedge bus.clk) begin
    if (bus.we) mem[bus.addr] <= bus.wdata;
    bus.rdata <= mem[bus.addr];
  end
endmodule

Signals are accessed with dot notation — bus.addr, bus.rdata — just like struct fields.

Interfaces can also contain functions that operate on their signals. The function body has direct access to the interface's own signals — no extra argument needed. This string-returning function is a simulation helper for the testbench:

function string sprint();
    return $sformatf(...);
endfunction

Any module that holds the interface calls it as bus.sprint(). Note: $sformatf() is like $display() but returns a string instead of printing to the console.

System Verilog also has classes, which are like structs with methods, and support inheritance and polymorphism. Classes cannot be synthesized, but are used heavily in UVM.

Testbench

The testbench creates the interface instance and passes it to both the SRAM and the initial block. After each write and read it calls bus.sprint(), checks the formatted snapshot, and checks the returned data. A final PASS means both the interface method and the SRAM behavior are correct.
