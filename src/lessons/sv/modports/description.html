The SRAM bus is shared by a stimulus source and a memory model. If both sides can write every signal, a typo can let the source overwrite read data or let the memory overwrite an address. A modport gives each connected module a direction-checked view:

                 shared mem_if
             ┌────────────────────┐
 initiator ─►│ we, addr, wdata    │  drives commands
 initiator ◄─│ clk, rdata         │  reads result
             │                    │
 target    ◄─│ we, addr, wdata,clk │  reads commands
 target    ─►│ rdata              │  drives result
             └────────────────────┘

Start with the general shape:

interface <name> ([input|output] <type> <port>, ...);
    // Signal declarations
    <type>       <signal>;
    <type> [N:0] <signal>;
    ...
    // Modport declarations
    modport <name> (output <signals>, input <signals>);
    modport <name> (input  <signals>, output <signals>);
endinterface

Without restrictions, any module connected to an interface can drive any signal — including signals it should only read. The initiator should drive we, addr, and wdata, while the SRAM should drive only rdata. The direction is written from the connected module's point of view:

modport initiator(output we, addr, wdata, input clk, rdata);
modport target   (input  we, addr, wdata, clk, output rdata);

The port qualifier .target then enforces that the SRAM can only drive rdata:

module sram (mem_if.target bus);   // compile error if sram writes bus.addr
  ...
endmodule

If sram tried to assign bus.addr, the tool would catch a port-direction error at compile time — before a silent mismatch reached a waveform.

Open mem_if.sv and add the two modport declarations. Include clk in the target's input list: sram.sv reads bus.clk, so omitting it is a direction error too. Without the declarations, the mem_if.target port in sram will fail to resolve.

In Part 3 the UVM driver holds a virtual mem_if — a reference to the interface instance created in tb_top. The virtual keyword is what lets a class-based component (which has no ports) reach down into the actual signal wires to drive the SRAM.

Testbench

The testbench uses the bare interface instance, which has unrestricted access for this compact example; the SRAM is the side whose view is enforced through mem_if.target. Once the modports are in place, the target port compiles, and the write-then-read sequence confirms the 1-cycle registered latency.
