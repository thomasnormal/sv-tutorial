So far we've been writing arrays and vectors with fixed widths, like [7:0]. Later we will discuss dynamic arrays, arr[], associative arrays, arr[string], and queues, int q[$], which add more flexibility. These testbench-oriented containers are not the focus of this synthesizable RTL lesson. Instead we will use compile-time parameters to create flexible, reusable modules: 

module sram #(parameter int DEPTH = 16, ...) (
  // ... ports ...
); ... endmodule

Parameters specified at instantiation: 

sram #(.DEPTH(8),   .WIDTH(4))  u_small(...);
sram #(.DEPTH(256), .WIDTH(16)) u_large(...);

We can apply some system functions, like $clog2 and $bits at compile time. For this lesson, use $clog2(DEPTH) for the minimum number of address bits.

Task: Add parametrization to sram.sv. Add the parameter block to the module header, derive a localparam for the last valid address, then replace the hardcoded dimensions with parameter-derived equivalents: use $clog2(DEPTH) for the address port, WIDTH for both data ports and each memory element, and the derived last address for the memory range. A localparam is an internal constant: callers can choose DEPTH and WIDTH, but cannot override the implementation's last-index calculation.

Always use $clog2 for address widths derived from depth parameters — it automatically adjusts when the depth changes, so the address bus is always exactly the right size. Derive the final memory index from DEPTH too, so the same source works for every instance.
