When several requesters want one SRAM port at the same time, the controller needs a deterministic winner. A priority encoder turns a request vector into the index of the highest-priority request, so arbitration is visible in one small combinational block.

The pattern

Start with the general shape. Put the most important pattern first; the first matching item wins:

always_comb begin
  casez (<request_vector>)
    <highest-bit>?: <highest-grant>;
    <next-bit>??:  <next-grant>;
    ...
    default:       <no-request-result>;
  endcase
end

casez is a case statement that treats ? and high-impedance Z bits as wildcards. In a pattern such as 4'b1???, only the leftmost bit matters; each ? can match either 0 or 1. Unlike casex, casez does not hide an unknown X in the request.

For priority_enc.sv, req[3] is highest priority and req[0] is lowest. The grant output carries the winning index, while valid says whether any request was present. The default branch handles 4'b0000 and gives both outputs a known idle value.

Exercise

Add the four missing casez branches in descending priority. Use 4'b1???, then 4'b01??, then 4'b001?, and finally 4'b0001. In each branch, assign the encoded grant and assert valid on separate lines. Leave the default branch as the no-request result.

Testbench

The starter testbench tries no request, each single-bit request, and overlapping requests such as 0111 and 1111. The printed grant value makes the priority decision visible in the log, and the waveform shows the request, winner, and valid flag changing together. It prints PASS only when every expected result matches.
