As the SRAM grows, the same width appears in ports, temporary signals, and testbench variables. Repeating logic [7:0] everywhere makes a width change a search-and-replace job. A typedef gives that shape one meaningful name that every module can reuse.

The pattern

Declare an alias in a package, then import the package before using the alias in a module port:

package <package_name>;
  typedef logic [N-1:0] <type_name>;
endpackage

import <package_name>::*;
module <module_name> (
  input  <type_name> a,
  output <type_name> y
);
  <type_name> temporary;
endmodule

typedef creates an alias; it does not add storage or change the bits. The _t suffix is a common naming convention for named types. The package is a namespace so the alias has one definition shared by the design and its testbench.

One shape, many uses

The alias can be used in a port declaration, a local variable, or a testbench signal. If the package changes the width later, every use keeps the same named contract.

Exercise

Open typedef_lab.sv. In typedef_pkg, define data_t as an 8-bit logic vector and lane_t as a 2-bit logic vector. Then use those aliases for the intermediate signals and connect the sum, XOR result, and copied lane with continuous assignments. The testbench uses the aliases too, so the design and its checks share the same type names.

Testbench

The testbench drives two input pairs and two lane values, then checks the derived result and the copied alias-typed lane. The printed values make the bit widths visible while the shared type names keep declarations compact.
