$readmemh loads hexadecimal words from a text file into an unpacked memory array. The file can contain four-state digits, so x and z preserve unknown and high-impedance values; underscores are legal separators within a number.

Template

logic [<width-1>:0] <memory> [<low>:<high>];
$readmemh("<file>", <memory>, <start>, <finish>);

This exercise loads three words into addresses 0 through 2. The first word is 65 bits wide, including a leading 1; the third includes a leading z. Change the starter's packed width so the memory can preserve every bit from the file.

IEEE 1800-2023 §21.4 defines $readmemb and $readmemh, including optional start and finish addresses. Section §21.4.1 says an unpacked array of packed data is loaded one packed element at a time. The file format permits hexadecimal digits, x, z, and underscores.

The runnable solution is qualified against Mox landing commit e7da9630dcd, which adds native interpreter and compile-mode support for wide, non-power-of-two four-state readmem values. The pinned browser WASM is older than this landing and is not treated as AOT evidence.
