Assertions are most useful when they stay beside the design they check without becoming part of the design's source. A bind statement attaches a checker to an existing module from outside that module, so the same counter RTL can be reused in simulation, synthesis, and verification.

The pattern

module <checker>(
  input logic clk,
  input logic <signals>
);
  // properties and assertions
endmodule

bind <target_module> <checker> <instance> (
  .clk(clk), .<signal>(<signal>)
);

The checker declares ports for the signals it observes. The bind names the target module, creates one checker instance, and connects those ports to signals in every target instance. The target module stays unchanged.

Exercise

Open counter_check.sv. Complete the property so an enabled counter increments on the following clock, then bind counter_checker to counter with named port connections. The supplied counter.sv is the same interface used earlier; leave it untouched. Run the testbench to see the counter count, hold, and reset while the bound assertion observes it from outside.

Testbench

The testbench drives the target counter through three phases and prints the observed values. The final PASS is printed only when the counter behavior is correct; the bound assertion is an additional check attached without changing the target module.
