A burst-read property can fail silently when its trigger never happens. Ordinary implication (|-> and |=>) passes in that case, so a passing report may only mean that the test never reached the interesting behavior. The followed-by operators make a missing antecedent a failure, which exposes an unexercised protocol.

The pattern

sequence <event>;
  <start> ##1 <step> ##1 <step>;
endsequence

property <must_follow>;
  @(posedge clk) <event> #-# <check>;
endproperty

property <must_follow_later>;
  @(posedge clk) <event> #=# <check>;
endproperty

#-# starts the property on the same cycle that the sequence ends. #=# starts it one cycle later. Both operators require the sequence to match; this is the non-vacuous behavior that ordinary |-> and |=> do not provide.

Exercise

Open followed_by.sv. Define a three-event burst_read sequence, then complete the overlapped #-#, non-overlapped #=#, and ordinary |=> properties. Click Verify: bounded model checking explores all input traces and shows a counterexample for the completed syntax exercise. Compare which operator starts data_ok on the sequence endpoint and which one starts a cycle later.
