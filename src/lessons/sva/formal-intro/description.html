Simulation checks one path through time. BMC asks a sharper question: can any input sequence break this property before the bound?

Simulation:  inputs → [testbench] → one execution trace → pass/fail

BMC:         inputs → [all possible sequences up to depth N]
                              ↓
                    counterexample found? → FAIL
                    no counterexample?    → NO COUNTEREXAMPLE (within depth N)

There is no testbench needed for BMC. The tool treats all inputs as free variables and tries to find a counterexample. If it cannot find one within the bound, the result is no counterexample within the explored depth — a bounded result, not an unbounded proof.

The previous implication lesson introduced |=>; now use it inside a bounded proof. Open top.sv. The 4-bit counter and an assertion skeleton are provided. Complete the one-cycle reset_event sequence, use it to check that when rst is high cnt is zero on the next cycle, and assert the named property.

Press verify to have BMC check every possible input sequence up to the bound. The log labels an unsat result as PROVED within the BMC bound and a sat result as COUNTEREXAMPLE FOUND.

The starter also includes tb.sv. Run it before solving to watch reset clear the counter and the counter advance; after solving, the same trace checks the expected values and prints PASS. Run answers "what happened on this trace?" while Verify answers "could any trace fail before N?"

BMC is bounded: a proof at depth N does not guarantee correctness at depth N+1. Full unbounded proof requires induction or deeper techniques — but for reset properties and most pipeline assertions, a modest bound is sufficient.
