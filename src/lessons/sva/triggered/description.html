A protocol monitor often needs a clean done pulse: a DMA request has finished its busy phase, so the response window can start. Repeating the request sequence everywhere makes the checker brittle. Every named sequence has a built-in method .triggered that is true at the clock tick where the sequence reaches its endpoint:

sequence s_req_done;
  @(posedge clk) req ##1 !busy;
endsequence

// .triggered is true at the clock tick where s_req_done reaches its endpoint
s_req_done.triggered |-> ...

This lets you build modular properties: define a sequence once, then reference its endpoint from multiple properties without duplicating the sequence body.

The related .matched method is useful when a sequence is composed across clocks. It reports the source sequence's endpoint result at the first sampling event of the destination clock; same-clock composition remains valid, while .triggered directly tests the endpoint at that point (IEEE 1800-2023 §16.13.5).

Open trigger_check.sv and complete the property: when the request sequence ends, ack must arrive within 3 cycles.

This builds on sva/sequence-basics: the sequence still describes a multi-edge event, while .triggered turns its endpoint into a reusable Boolean trigger. The starter includes tb.sv with one request, a busy-to-idle transition, and an acknowledgement one edge after completion. Run it before solving to follow the endpoint; the solved trace prints PASS.

.triggered can also be used inside another sequence. IEEE 1800-2023 §16.9.11 shows an expression such as reset ##1 inst ##1 e1.triggered ##1 branch_back; the method tests the endpoint at that point without requiring the source sequence to start there.
