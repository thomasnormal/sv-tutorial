The previous lessons built a UVM sequence item and sent it through a driver. Real tests need to steer that same item toward boundary cases, special operations, or a broader spread without editing the reusable class. UVM's constraint solver supports three ways to do that.

The general shapes are:

void'(<item>.randomize() with { <extra_rule>; });
constraint <name> { <distribution_or_rule>; }
<item>.<name>.constraint_mode(0);
class rules ────────┐
inline with { ... } ──┼──► legal values for this call
mode(0) ──────────────┘    (turns one named rule off)

1 — Add a rule for one call

An inline with { } block is AND-ed with every active class constraint:

void'(item.randomize() with { field == value; });

It narrows this call only. It does not replace a class constraint or change later calls.

2 — Weighted distribution with dist

mem_item already declares a weighted_c constraint that biases addr toward boundary values 0 and 15 using a dist distribution:

constraint weighted_c {
  addr dist { [0:0] := 3, [1:14] := 1, [15:15] := 3 };
}

The := weight syntax assigns a relative weight. Here boundaries are three times as likely as any interior address.

3 — Turning a constraint on or off

Call constraint_mode(0) to disable a named constraint for all subsequent calls, or constraint_mode(1) to re-enable it. Scenario 3 samples 160 items and checks that at least 130 land in the 14-value interior. That large sample makes the difference between the weighted and unconstrained distributions visible without relying on one lucky draw.
