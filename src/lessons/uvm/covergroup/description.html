Assertions answer "did something illegal happen?" — functional coverage answers "did we exercise the scenarios we care about?". An SRAM test can pass while quietly skipping an address or every write, so we need evidence that the stimulus reached the scenarios we planned.

A reusable coverage collector has this shape:

class <collector> extends uvm_subscriber #(<item_type>);
  covergroup <group>;
    <coverpoints>
  endgroup
  function void write(<item_type> item); <group>.sample(); endfunction
endclass

In UVM, coverage lives in a uvm_subscriber — a component with a built-in analysis export. Every transaction written to it calls write(), which samples the covergroup.

A covergroup collects related measurements. Each coverpoint turns one transaction field into named bins (buckets of values); sample() records the current item, and get_coverage() reports the percentage of bins hit. The question for this SRAM is simple: did we see every address in both read and write modes?

An empty covergroup has no bins to miss, so some simulators report it as 100% covered. The starter includes a coverage_ready guard to keep that vacuous result from looking like a completed lesson.

Open mem_coverage.sv and complete three things:

  1. Add cp_addr coverpoint — one bin per SRAM address (0–15) — proves every memory location was accessed
  2. Add cp_we coverpoint — two bins, one for reads and one for writes
  3. Set coverage_ready = 1, then rerun until the supplied check reaches 100%

Coverage holes are most often found by removing or widening constraints and re-running. If cp_addr misses addresses 12-15, those addresses were never generated — adjust the sequence stimulus to cover the full range.
