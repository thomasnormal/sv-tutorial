mem_item object       UVM driver             SRAM interface
┌──────────────┐      get_next_item      ┌───────────────┐
│ we addr data │ ──────────────────────► │ we addr wdata │
│       rdata  │ ◄──── item_done ────── │      rdata    │
└──────────────┘      virtual mem_if    └───────────────┘

The previous lesson's sequence handed mem_item objects to a logging driver. Now the driver is where the UVM world meets RTL: it pulls one transaction, converts its fields to pin-level stimulus, captures the result, and signals completion. A driver has this shape:

class <name> extends uvm_driver #(<item_type>);
  virtual <interface_type> vif;
  task run_phase(uvm_phase phase);
    <item_type> req;
    seq_item_port.get_next_item(req);
    // drive req through vif
    seq_item_port.item_done();
  endtask
endclass

The basic loop is:

  1. Call seq_item_port.get_next_item(req) — blocks until the sequencer has a transaction
  2. Wait for the clock edge, then drive the interface signals from the item fields
  3. Wait one more clock edge so the transaction boundary has settled, then capture the SRAM's combinational read data
  4. Call seq_item_port.item_done() — unblocks the sequence's finish_item

This lesson's SRAM has a combinational read port: once the address is present, rdata reflects the selected word. The driver still uses the next clock edge as a clean transaction boundary before copying that response back into the item:

         cycle N          cycle N+1
clk   ____/‾‾‾‾\____/‾‾‾‾\____
addr  ──────[addr]────────────────
we    ──────[we  ]────────────────
wdata ──────[data]────────────────
rdata ──────[data]────────────────   ← capture after boundary

The DUT is accessed through a virtual interface handle retrieved from uvm_config_db. Open mem_driver.sv and complete both phases:

  • In build_phase: call uvm_config_db::get() to retrieve the virtual interface — if it fails, call `uvm_fatal
  • In run_phase: drive we, addr, and wdata onto the interface, then capture rdata after the boundary edge

The virtual interface is the only bridge from the dynamic class world into the static module world. It must be set in tb_top before run_test() is called, and get by every component that needs DUT access.
