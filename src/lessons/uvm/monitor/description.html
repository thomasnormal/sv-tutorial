SRAM pins             passive observer          checker
valid, we, addr, rdata ─► mem_monitor ──► ap ───► write(item)
                         samples only       fan-out   shadow memory
                         never drives                 compare/update

The driver already turns a transaction into pins. This lesson follows the same operation back in the other direction: a monitor samples one completed cycle, rebuilds a mem_item, and broadcasts it. The monitor is passive — it never drives the DUT.

The monitor's uvm_analysis_port is the hand-off. The driver's valid strobe marks the one clock where the pins represent a complete transaction:

class <name> extends uvm_monitor;
  virtual <interface_type> vif;
  uvm_analysis_port #(<item_type>) ap;
  task run_phase(uvm_phase phase);
    @(posedge vif.clk);
    if (vif.valid) ap.write(<captured_item>);
  endtask
endclass

One subscriber is the scoreboard. Its shadow memory gives each observed read a concrete expected value:

  driver writes addr=3, data=42
       │                        │
       ▼                        ▼
  DUT SRAM  [3]=42        shadow[3]=42   ← scoreboard tracks this
       │
  driver reads addr=3
       │                        │
       ▼                        ▼
  DUT rdata=42    compare ══► shadow[3]=42   PASS ✓
  DUT rdata=99    compare ══► shadow[3]=42   FAIL ✗

The scoreboard subscribes using a uvm_analysis_imp (implementation, not an import). Every broadcast calls its write() method automatically. The supplied sequence performs writes followed by reads at the same addresses, so the shadow model has something real to check. Open mem_scoreboard.sv and complete write():

  • Write transaction: update shadow[item.addr] with item.wdata
  • Read transaction: compare item.rdata to shadow[item.addr] — increment pass_count or fail_count and log accordingly

The analysis port is one-to-many: the monitor does not know how many subscribers are connected. You can attach a coverage collector alongside the scoreboard by connecting both to the same port — the monitor code does not change at all.
