You've built and formally verified an SRAM in pure SystemVerilog. The first UVM question is simpler: how does a test keep its run alive long enough to do useful work, then report what happened? UVM gives that lifecycle a reusable class shape and a reporting service shared by every component.

The general test shape is:

class <name> extends uvm_test;
  task run_phase(uvm_phase phase);
    phase.raise_objection(this);
    // report or drive work here
    phase.drop_objection(this);
  endtask
endclass

UVM provides four reporting macros that include automatic component-name and file/line information:

  • `uvm_info(ID, msg, verbosity) — informational; gated by verbosity level
  • `uvm_warning(ID, msg) — always printed; increments warning count
  • `uvm_error(ID, msg) — always printed; increments error count; simulation continues
  • `uvm_fatal(ID, msg) — always printed; immediately calls $finish

A UVM run starts with run_test("test_name") from the static top-level module. UVM constructs the named test class and drives it through a fixed sequence of phases. Only run_phase consumes time; the other phases set up or summarize the run.

run_test("test_name")
       │
       ▼
  run_phase:  raise ──► report/work ──► drop
       │                         │
       └── objection keeps time ──┘
              │
              ▼
       check_phase → report_phase

run_phase is the only time-consuming phase. Simulation does not advance past it until all components drop their objections.

This first UVM test moves the timing discipline from the initial block in sv/tasks-functions into a class method. The later driver will reach the same SRAM bus through the virtual interface from sv/interfaces; for now, concentrate on one complete raise/report/drop cycle.

Open my_test.sv and complete the run_phase body:

  1. Raise an objection to hold simulation open
  2. Print an info message and an error message using the UVM macros
  3. Drop the objection to let simulation end
  4. Print the PASS completion marker after the drop

Forgetting to call drop_objection is the most common beginner UVM bug — simulation will run forever. Always pair raise with drop.
