A sequence item is the transaction object that carries one SRAM operation through a UVM testbench. In uvm/reporting, the test's run_phase controlled when work happened; now we give that phase a typed object to create and report.

The general shape is:

class <name> extends uvm_sequence_item;
  rand <type> <stimulus_field>;
  <type> <result_field>;
  `uvm_object_utils_begin(<name>)
    `uvm_field_int(<stimulus_field>, UVM_ALL_ON)
  `uvm_object_utils_end
  constraint <name> { <legal_values>; }
endclass

Fields marked rand are randomizable. Constraints narrow the random space to legal values. The factory registration macro enables type overrides and auto-generates print(), copy(), and compare(). Open mem_item.sv and add three rand fields for we, addr, and wdata, one non-random rdata, their field macros, and a read-only-by-default constraint.

sequence  →  sequencer  →  driver  →  SRAM pins
   creates       arbitrates      translates
   mem_item      item flow       we/addr/data

Always create items through the factory: adder_item::type_id::create("item") — not with new directly. Factory creation enables test-level type substitution without changing any sequence code.
